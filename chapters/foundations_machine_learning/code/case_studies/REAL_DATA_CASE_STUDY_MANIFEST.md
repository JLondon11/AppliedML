The Chapter 1 empirical-application policy is: a case study/application is not
closed by prose or a conceptual illustration alone. It must have executable
section-specific code, named real data, an explicit split/protocol, numerical
metrics, and one or more result/output figures generated by that code.

## Measured closure results

Medical diagnosis (70/30 stratified holdout, seed 1729):

- Logistic regression: accuracy 0.976608, balanced accuracy 0.971890,
  F1 0.981481, ROC-AUC 0.994597.
- Random forest: accuracy 0.959064, balanced accuracy 0.954731,
  F1 0.967442, ROC-AUC 0.995765.

Edge quantization (70/30 stratified holdout, seed 1729):

- Float64 logistic model: accuracy 0.974074; coefficient storage 5120 bytes.
- Symmetric int8 coefficients: accuracy 0.972222; coefficient storage 640 bytes.
- Storage reduction: 8x, with an absolute accuracy change of 0.001852.

## Publication integration gate

Before Chapter 1 is marked COMPLETE, every manuscript application/case-study
heading must map to an entry here (or an additional section-specific
implementation), and the generated result figure must be inserted, cited,
captioned with dataset/model/protocol provenance, and analyzed in the
corresponding Results/Benchmark Comparison prose. Simulated/synthetic result
panels cannot satisfy an empirical case-study requirement.
